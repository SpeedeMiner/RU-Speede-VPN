# RU-Speede-VPN

Клиентские профили маршрутизации на общей политике для **Happ**, **Mihomo**, **sing-box** и **Xray/V2Ray**. Геоданные берутся из [Geosite-ru-light](https://github.com/SpeedeMiner/Geosite-ru-light/tree/release) и [Geoip-ru-server](https://github.com/SpeedeMiner/Geoip-ru-server/tree/cdn). Репозиторий не содержит VPN-серверов, ключей или подписок.

## Остальные клиенты

| Клиент | Профиль | Что настроить |
| --- | --- | --- |
| Mihomo | [Полный YAML](mihomo/ru-speede-vpn.yaml) · [только правила](mihomo/rules-only.yaml) | Заполните шаблон VLESS Reality `GER` в полном YAML. Для существующей конфигурации перенесите `rule-providers` и `rules` из второго файла и проверьте наличие группы `PROXY`. MRS скачиваются через `PROXY`, а фрагмент `rules-only.yaml` не требует `DNS-OUT`. |
| sing-box 1.12 / 1.13 | [Профиль JSON](sing-box/ru-speede-vpn.json) | Заполните шаблон VLESS Reality `GER`. Все 19 SRS скачиваются через `PROXY` и обновляются раз в сутки. |
| Xray / V2Ray | [Профиль JSON](xray/ru-speede-vpn.json) | Замените первый outbound с тегом `proxy` на свой, сохраните `direct` и `block`. Скачайте DAT и для V2Ray подготовьте совместимую копию GeoIP. |

**Mihomo.** Замените `server`, `uuid`, `servername`, `public-key` и при необходимости `short-id` в `GER` на данные своего сервера. TUN со стеком `mips` включён и при обычном запуске меняет системную маршрутизацию. Для запуска нужны права на создание TUN и свободный DNS-порт 53. Смешанный порт `7890` доступен из разрешённых LAN-подсетей. DNS слушает на `0.0.0.0:53` отдельно от этого списка, поэтому на узле с публичным интерфейсом ограничьте доступ к DNS через файрвол.

**sing-box.** Заполните `server`, `uuid`, `tls.server_name`, `tls.reality.public_key` и при необходимости `short_id` в `GER`. Рабочий `GER` нужен уже при первой загрузке SRS. Профиль включает TUN с автоматической маршрутизацией и смешанный вход `127.0.0.1:7890`. При совместном запуске с Mihomo измените один из портов `7890`. Домены из прямых категорий и с суффиксами `ru`, `kz`, `su`, `by`, `xn--p1ai` используют `dns-direct`, если не сработало более приоритетное DNS-правило. CIDR-правила проверяют известный ядру IP назначения без принудительной подстановки IP для каждого домена.

Для Xray/V2Ray демонстрационный outbound указывает на SOCKS5 `127.0.0.1:1081`. Поднимите там своё подключение или замените outbound перед запуском. Вход слушает только `127.0.0.1:1080`. Прямого резервного выхода для `PROXY` в этих профилях нет.

В Mihomo, sing-box и Xray/V2Ray для DoH используются имена `dns.google` и `common.dot.dns.yandex.net`, чтобы TLS проверял сертификаты по имени. Happ сохраняет IP-URL из эталона. Если ваша версия Happ сообщает об ошибке сертификата DoH, проверьте профиль с именами серверов вместо IP в URL, не отключая проверку TLS. [Google Public DNS](https://developers.google.com/speed/public-dns/docs/doh) · [Яндекс DNS](https://dns.yandex.ru/).

**DAT для Xray/V2Ray** — [geosite_RU.dat](https://raw.githubusercontent.com/SpeedeMiner/Geosite-ru-light/release/geosite_RU.dat) и [geoip_RU.dat](https://raw.githubusercontent.com/SpeedeMiner/Geoip-ru-server/cdn/geoip_RU.dat). Сохраните эти имена и перезапускайте ядро после обновления файлов. При необходимости задайте каталог ресурсов через `XRAY_LOCATION_ASSET` или `V2RAY_LOCATION_ASSET`.

Xray читает оригинальные DAT. Для V2Ray используйте отдельный каталог ресурсов, поскольку V2Ray 5.53.0 не принимает `::ffff:0.0.0.0/96` внутри `PRIVATE`. Команды создают совместимый `geoip_RU.dat`, не меняя категорию RU или исходный файл. Повторяйте подготовку после обновления GeoIP.

```bash
mkdir -p v2ray-assets
cp geosite_RU.dat v2ray-assets/
python3 scripts/prepare_v2ray_geoip.py geoip_RU.dat v2ray-assets/geoip_RU.dat
V2RAY_LOCATION_ASSET="$PWD/v2ray-assets" v2ray run -c xray/ru-speede-vpn.json
```

<details>
<summary>Karing (iOS / Android / Desktop)</summary>

1. Скачайте [sing-box/ru-speede-vpn.json][sing-box-json], заполните параметры своего VLESS Reality в `GER` и добавьте локальный файл через **Добавить профиль → Импорт файла профиля**. 2. Для собственных правил откройте **Настройки → Маршрутизация (Diversion) → Правила → Изменить → Пользовательские группы**. Создайте группы и добавьте в них элементы **Rule Set** с прямыми URL. Назначьте `BLOCK` для [geosite_BLOCK.srs][geosite-block-srs] и `DIRECT` для [geosite_RU.srs][geosite-ru-srs], [geoip_RU.srs][geoip-ru-srs] и [geoip_PRIVATE.srs][geoip-private-srs]. Сохраните и переподключитесь. [Редактор правил Karing](https://karing.app/en/tutorial/custom-diversion).
3. Это базовый набор. Для полного набора категорий и явных исключений используйте `route.rule_set` и `route.rules` из [JSON sing-box][sing-box-json] как эталон при настройке групп.

</details>

<details>
<summary>Streisand (iOS / macOS)</summary>

1. **Xray.** Откройте **Настройки → Маршрутизация → Настройки → Геофайлы (Assets)**. Добавьте URL для [geosite_RU.dat][geosite-dat] и [geoip_RU.dat][geoip-dat], затем обновите ресурсы. Перенесите правила из массива `routing.rules` файла [Xray JSON][xray-json], сопоставив `block`, `proxy` и `direct` с действиями клиента. Если клиент не использует входящий тег `speede-dns`, правило для этого тега переносить не нужно. Включите маршрутизацию. [Пример добавления геофайлов](https://bolotov.dev/blog/2026/02/04/vpn-route).

## Как выбирается маршрут

| Приоритет | Действие | Источник решения |
| --- | --- | --- |
| 1 | BLOCK | `BLOCK`, `WIN-SPY` и явные IP-исключения |
| 2 | PROXY | Google Play, GitHub, Twitch Ads, YouTube, Telegram, `4pda.to`, домен вложений Discord и явные IP-исключения |
| 3 | DIRECT | RU и остальные прямые категории из эталона, локальные адреса, GeoIP RU |
| 4 | PROXY | Всё, для чего не нашлось правила |

Правила сравниваются с теми данными о назначении, которые есть у ядра. Happ и Xray/V2Ray используют `IPIfNonMatch`: при совпадении домена второй проход по разрешённому IP не выполняется. В Xray/V2Ray нельзя добавлять завершающий catch-all в `routing.rules`: он предотвратит второй проход. Маршрут по умолчанию задаёт первый outbound. В Mihomo и sing-box разрешение имени и наборы локальных адресов реализованы средствами соответствующего ядра, поэтому результаты могут отличаться там, где домен и его IP подпадают под разные правила. В профиле Happ оба домена записаны без префиксов. В остальных профилях для вложений Discord сохраняется точное совпадение с указанным именем, а для `4pda.to` — совпадение с доменом и его поддоменами.

Mihomo использует MRS (`domain` и `ipcidr`) и `GEOIP,PRIVATE,DIRECT,no-resolve`. Для этого правила полному профилю нужен [стандартный GeoIP DAT MetaCubeX](https://github.com/MetaCubeX/meta-rules-dat/releases/download/latest/geoip.dat), поскольку Mihomo проверяет наличие категории CN при загрузке DAT. Если автоматическая загрузка недоступна, сохраните этот файл как `GeoIP.dat` в рабочем каталоге ядра. Маршрут RU берётся из `geoip_RU.mrs`, а не из стандартного DAT. sing-box использует бинарные SRS и `ip_is_private`. Xray/V2Ray читают DAT через `ext:`. Значения DNS hosts для двух доменов ФНС взяты из эталона. Маршрутизация HTTP/SOCKS-клиента не меняет системный DNS сторонних приложений.

## Обновление и проверка

Эталон политики — [шаблон Happ](happ/ru-speede-vpn.template.json). При изменении правил перегенерируйте все клиенты. Расписание Happ — ежедневно в 04:30 UTC, также есть ручной запуск в GitHub Actions. Один Unix Timestamp используется в обоих URL геобаз, `LastUpdated` и `lastUpdatedDate`. Он показывает момент генерации профиля, а не время публикации обеих баз.

```bash
python3 -m pip install -r requirements-dev.txt
python3 scripts/update_happ_profile.py
python3 scripts/render_profiles.py
python3 -m pytest -q
python3 scripts/update_happ_profile.py --check
python3 scripts/render_profiles.py --check
python3 scripts/validate_clients.py
```

Последняя команда проверяет конфигурации на Linux x86-64 официальными бинарниками с зафиксированными SHA-256. Ей нужен сетевой доступ к GitHub для скачивания бинарников и геоданных.
